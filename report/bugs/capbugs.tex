\chapter{Bugs Detected and Fixed} \label{cap:bugs}

This chapter documents the defects detected by the automated tests and the corresponding corrections in the production implementation. Each scenario is part of the default \texttt{mvn test} regression suite.

\section{Ticketmaster query parameters were double-encoded}

The test \texttt{ticketmasterProviderEncodesQueryParameters} detects a bug in \texttt{TicketmasterProvider}. Searches containing spaces must be sent as \texttt{\%20}; the defective behavior sends \texttt{\%2520}, which means an already encoded \texttt{\%20} sequence is encoded a second time.

\textbf{Correction:} \texttt{TicketmasterProvider.search(...)} builds the request through \texttt{RestClient}'s URI builder. Query values such as the search keyword and API key are passed as raw parameter values and encoded exactly once by the client.

\section{Discovery aggregation aborted when one provider threw}

The test \texttt{searchContinuesWhenOneConfiguredProviderThrows} detects a robustness bug in \texttt{DiscoveryService}. A \texttt{RuntimeException} from one provider must not escape the aggregation loop and prevent later providers from being queried.

\textbf{Correction:} \texttt{DiscoveryService.search(...)} catches provider runtime failures, logs the failed provider, and continues merging results from the remaining configured providers.

\section{iCalendar output did not fold long content lines}

The test \texttt{renderFoldsLongContentLinesAtSeventyFiveCharacters} detects an RFC 5545 compatibility bug in \texttt{ICalService}. Long fields such as \texttt{SUMMARY} must not be emitted as a single physical line longer than the iCalendar limit.

\textbf{Correction:} \texttt{ICalService.appendLine(...)} folds long content lines at 75 characters and prefixes continuation lines with a space.

\section{Registration accepted blank required fields server side}

The test \texttt{registerRejectsBlankRequiredFieldsServerSide} detects an input validation bug in \texttt{UserService}. Blank usernames, emails, and passwords must not bypass browser side \texttt{required} attributes when submitted by a direct HTTP client.

\textbf{Correction:} \texttt{UserService.register(...)} rejects blank or null username, email, and password values before checking duplicates, encoding passwords, or saving users.

\section{Meeting proposal did not reject organizer overlaps}

The test \texttt{proposeRejectsOrganizerOverlapBeforeSaving} detects a scheduling bug in \texttt{MeetingService}. A proposed meeting must not be saved when it overlaps the organizer's existing calendar.

\textbf{Correction:} \texttt{MeetingService.propose(...)} checks the organizer with \texttt{MeetingRepository.findOverlapping(...)} before creating and saving the meeting.

\section{Meeting proposal did not reject invitee overlaps}

The test \texttt{proposeRejectsInviteeOverlapBeforeSaving} detects a second scheduling bug in \texttt{MeetingService}. Invitees must not receive pending invitations for slots where they already have meetings.

\textbf{Correction:} each real, non duplicate invitee is checked for overlapping meetings before being added to the proposal. If any participant is busy, the service rejects the proposal and does not save it.

\section{Copied discovered events did not reject calendar overlaps}

The test \texttt{copyFromDiscoveredRejectsUserOverlap} detects another overlap bug in \texttt{MeetingService}. A user must not import a discovered event into an already occupied time slot.

\textbf{Correction:} \texttt{MeetingService.copyFromDiscovered(...)} computes the event end time, checks the user's existing calendar for overlaps, and only saves the copied event when the slot is free.

\section{Unknown invite response actions were accepted as declines}

The test \texttt{respondAcceptsOnlyKnownActions} detects a validation bug in \texttt{MeetingController}. Every action other than \texttt{accept} must not be treated as \texttt{DECLINED}, malformed values such as \texttt{maybe} must be rejected instead of mutating invitation state.

\textbf{Correction:} \texttt{MeetingController} accepts only explicit \texttt{accept} and \texttt{decline} actions. Any other value produces \texttt{400 Bad Request}.

\section{Responding to someone else's invite was not mapped to 404}

The test \texttt{userCannotRespondToSomeoneElsesInvite} detects missing HTTP error handling in the meeting response flow. When an authenticated user has no invite for a meeting, the service exception must become a clear HTTP response.

\textbf{Correction:} \texttt{MeetingController} translates the missing-invite error from \texttt{MeetingService.respond(...)} into \texttt{404 Not Found}.
