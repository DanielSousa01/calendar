The local verification command compiles the application, compiles the test sources, starts the required Spring contexts, runs the service unit tests, provider integration tests, REST/API integration tests, repository integration tests, and the Selenium end-to-end test.

The defect-detection tests run in this same default suite, so the corrected behaviors are verified together with the rest of the application.

\section{Continuous Integration}
 
Continuous Integration was configured in the branch using GitHub Actions. The workflow file is located at \texttt{.github/workflows/tests.yml} and defines a job named \texttt{test}. The workflow is triggered on pushes to \texttt{main} and on pull requests targeting \texttt{main}, so the test suite is executed automatically whenever changes are submitted through the normal repository workflow.

The CI job runs on an Ubuntu GitHub-hosted runner. It first checks out the repository with \texttt{actions/checkout}, then installs Temurin JDK 17 with \texttt{actions/setup-java}. After the Java environment is ready, the job executes:

\texttt{mvn clean test}

This command compiles the Spring Boot application and runs the full automated regression suite, including unit tests, integration tests, repository tests, REST/API tests, defect detection scenarios, and the Selenium end-to-end test. The CI result is therefore used as branch-level evidence that the test suite runs in a clean environment outside the developer machine.

The expected result for this branch is that CI completes the setup steps and passes the same suite as the local verification run: 61 tests executed, with 61 passing tests and no failures or errors.

The Selenium end-to-end test is included in the full run and passed. It starts an embedded Spring Boot web server on a random local port and launches headless Chrome through ChromeDriver.
