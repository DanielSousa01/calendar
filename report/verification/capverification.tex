\section{Local Verification Walkthrough}

The default local verification command compiles the application, compiles the test sources, starts the required Spring contexts, runs the service unit tests, provider integration tests, REST/API integration tests, repository integration tests, and the Selenium end-to-end test. It excludes tests tagged with \texttt{@Tag("bug")} and is expected to pass. The separate \texttt{bug-tests} profile runs only the known defect tests, which are expected to fail until the application implementation is corrected.

\section{Continuous Integration}
 
Continuous Integration was configured in the branch using GitHub Actions. The workflow file is located at \texttt{.github/workflows/tests.yml} and defines a job named \texttt{test}. The workflow is triggered on pushes to \texttt{main} and on pull requests targeting \texttt{main}, so the test suite is executed automatically whenever changes are submitted through the normal repository workflow.

The CI job runs on an Ubuntu GitHub-hosted runner. It first checks out the repository with \texttt{actions/checkout}, then installs Temurin JDK 17 with \texttt{actions/setup-java}. After the Java environment is ready, the job executes:

\texttt{mvn clean test}

This command compiles the Spring Boot application and runs the default automated regression suite, including unit tests, integration tests, repository tests, REST/API tests, and the Selenium end-to-end test. The CI result is therefore used as branch-level evidence that the test suite runs in a clean environment outside the developer machine.

The expected result for this branch is that CI completes the setup steps and passes the same default test suite as the local verification run: 38 tests executed, with 38 passing tests and no failures or errors. This confirms that the branch contains automated CI configuration for the normal regression suite.
